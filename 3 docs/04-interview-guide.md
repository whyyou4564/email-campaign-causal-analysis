# 面试讲解与常见问题

## 一、用一分钟讲项目

我用 Hillstrom 随机邮件实验补充已有的 MySQL 漏斗分析项目。先验证实验分组与特征平衡，再对访问、购买和消费做统计检验和 ITT 平均效应估计。随后用实验前特征建立响应预测和 S/T/X-Learner，按训练、验证、测试分开评价增益排序。最后在明确成本和购买贡献利润假设下，比较随机投放、响应预测投放、增益投放及全量发送，并用区间说明能否支持业务改善。

具体数值请以 README 和 resume-bullets 中本次运行结果为准；不要背诵尚未解释的指标。

## 二、为什么不能只做分类预测？

购买概率高的人可能不收邮件也会购买。响应预测排序倾向识别本来就会买的人；增益模型估计给邮件后概率改变多少。个体反事实不可同时观察，因此要用随机实验处理/对照组在独立样本上评价整体排序。

## 三、为什么 ATE 可以直接用均值差？

随机分配使处理与潜在结果在期望上独立，所以组间均值差是 ITT ATE 的估计。它依赖真实随机化和一致结果记录；SRM 与平衡只是检查，不能证明来源实验一定没有问题。

## 四、为什么 spend 不先去掉零值？

业务关心每位分配客户贡献多少收入。只保留购买者会筛选实验后的结果，也改变估计目标。零值和高消费值全部保留；Welch 允许方差不同，bootstrap 检查右偏分布下的不确定性。

## 五、为什么不用准确率评价增益模型？

购买稀少，全部预测“不买”也能获得很高准确率；更重要的是准确率没有衡量处理组相对对照组的增量。Qini/AUUC 与 Uplift@K 检查排序能否优先找到有增量的人，利润评价再加入成本假设。

## 六、如何防止用测试集选最好结果？

按三组分层固定 60/20/20。模型参数固定，验证集选择模型和比例，保存 policy_lock 后评价测试集。测试覆盖曲线只用于描述，不能把测试集峰值当作已验证的最优比例。

## 七、为什么还可能无法证明模型优于随机？

购买事件少，模型差值方差大；两模型都可能带来正收益，但两者差值区间仍跨零。应报告差值区间，承认增益建模不保证胜过简单规则，并用后续随机策略实验验证。

## 八、两个电商项目如何互补？

漏斗项目说明发生了什么、哪些阶段流失；邮件随机实验说明干预是否产生增量，并尝试在有限预算下选择客户。它们分别展示 SQL 指标口径与 Python 统计、因果推断、机器学习验证能力。
